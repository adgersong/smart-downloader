## 1. 问题描述

当前代码库中存在多处 API 地址硬编码，主要问题集中在：

1. **请求基础路径硬编码** - `src/services/request.ts`
2. **API 端点直接写死** - 多个页面组件直接使用 `fetch('/api/v1/xxx')`

## 3. 硬编码带来的问题

### 3.1 环境切换困难

```typescript
// ❌ 当前问题
// 开发环境：http://localhost:8000/api/v1
// 测试环境：http://test-api.example.com/api/v1
// 生产环境：https://api.example.com/v1

// 需要修改代码才能切换环境
const request = axios.create({
  baseURL: '/api/v1',  // 写死了！
});
```

### 3.2 API 版本升级麻烦

```typescript
// ❌ 从 v1 升级到 v2 需要修改多处
'/api/v1/systems'  → '/api/v2/systems'
'/api/v1/tasks'    → '/api/v2/tasks'
'/api/v1/files'    → '/api/v2/files'
```

### 3.3 测试成本高

- 无法轻松 Mock 不同环境的 API
- 单元测试依赖固定路径
- 集成测试需要修改代码

### 3.4 代码维护困难

- API 路径散落在各处，难以统计
- 重构时容易遗漏
- 新人难以理解 API 结构

## 4. 解决方案

### 方案 1: 环境变量（⭐⭐⭐⭐⭐ 强烈推荐）

**适用场景**: 多环境部署、CI/CD 流程

#### 4.1.1 创建环境变量文件

```bash
# .env.development
API_BASE_URL=/api/v1
API_TIMEOUT=30000

# .env.test
API_BASE_URL=http://test-api.example.com/v1
API_TIMEOUT=30000

# .env.production
API_BASE_URL=https://api.example.com/v1
API_TIMEOUT=60000
```

#### 4.1.2 Umi 配置读取环境变量

```typescript
// .umirc.ts
import { defineConfig } from '@umijs/max';

export default defineConfig({
  // ...其他配置
  define: {
    'process.env.API_BASE_URL': process.env.API_BASE_URL || '/api/v1',
    'process.env.API_TIMEOUT': process.env.API_TIMEOUT || '30000',
  },
  proxy: process.env.API_BASE_URL?.startsWith('http') 
    ? {} 
    : {
        '/api': {
          target: 'http://localhost:8000',
          changeOrigin: true,
        },
      },
});
```

#### 4.1.3 修改 request.ts

```typescript
// src/services/request.ts
import axios from 'axios';
import { history } from '@umijs/max';

const request = axios.create({
  baseURL: process.env.API_BASE_URL || '/api/v1',
  timeout: Number(process.env.API_TIMEOUT) || 30000,
});

// ... 拦截器保持不变
```

#### 4.1.4 使用方式

```bash
# 开发环境
npm run dev

# 测试环境
API_BASE_URL=http://test-api.example.com/v1 npm run build

# 生产环境
API_BASE_URL=https://api.example.com/v1 npm run build
```

### 方案 2: 集中管理 API 路径（⭐⭐⭐⭐⭐ 强烈推荐）

**适用场景**: API 路径统一管理、版本控制

#### 4.2.1 创建 API 配置文件

```typescript
// src/config/api.ts
const API_VERSION = 'v1';
const API_BASE = `/api/${API_VERSION}`;

export const API_CONFIG = {
  version: API_VERSION,
  timeout: 30000,
};

export const api = {
  // 组织管理
  organization: {
    list: `${API_BASE}/organizations`,
    detail: (id: number) => `${API_BASE}/organizations/${id}`,
    create: `${API_BASE}/organizations`,
    update: (id: number) => `${API_BASE}/organizations/${id}`,
    delete: (id: number) => `${API_BASE}/organizations/${id}`,
  },

  // 业务系统
  systems: {
    list: (orgId: number) => `${API_BASE}/systems?org_id=${orgId}`,
    detail: (id: number) => `${API_BASE}/systems/${id}`,
    create: `${API_BASE}/systems`,
    update: (id: number) => `${API_BASE}/systems/${id}`,
    delete: (id: number) => `${API_BASE}/systems/${id}`,
  },

  // 流程管理
  workflows: {
    list: `${API_BASE}/workflows`,
    detail: (id: number) => `${API_BASE}/workflows/${id}`,
    create: `${API_BASE}/workflows`,
    update: (id: number) => `${API_BASE}/workflows/${id}`,
    delete: (id: number) => `${API_BASE}/workflows/${id}`,
    preview: (id: number) => `${API_BASE}/workflows/${id}/preview`,
    generateFromText: `${API_BASE}/workflows/generate/from-text`,
    generateFromScreenshot: `${API_BASE}/workflows/generate/from-screenshot`,
    validate: (id: number) => `${API_BASE}/workflows/${id}/validate`,
    duplicate: (id: number) => `${API_BASE}/workflows/${id}/duplicate`,
  },

  // 任务管理
  tasks: {
    list: `${API_BASE}/tasks`,
    detail: (id: number) => `${API_BASE}/tasks/${id}`,
    execute: `${API_BASE}/tasks/execute`,
    cancel: (id: number) => `${API_BASE}/tasks/${id}/cancel`,
    retry: (id: number) => `${API_BASE}/tasks/${id}/retry`,
    logs: (id: number) => `${API_BASE}/tasks/${id}/logs`,
  },

  // 文件管理
  files: {
    list: `${API_BASE}/files`,
    download: (id: number) => `${API_BASE}/files/${id}/download`,
    preview: (id: number) => `${API_BASE}/files/${id}/preview`,
    delete: (id: number) => `${API_BASE}/files/${id}`,
  },

  // 下载历史
  downloads: {
    history: `${API_BASE}/downloads/history`,
    stats: `${API_BASE}/downloads/stats`,
  },
};
```

#### 4.2.2 统一使用方式

```typescript
// src/pages/System/index.tsx
import { api } from '@/config/api';
import request from '@/services/request';

// ❌ 之前
const response = await fetch('/api/v1/systems?org_id=1');
await fetch(`/api/v1/systems/${record.id}`, { method: 'DELETE' });

// ✅ 现在
const response = await request.get(api.systems.list(1));
await request.delete(api.systems.delete(record.id));
```

### 方案 3: Umi 内置配置（⭐⭐⭐ 推荐）

**适用场景**: 简单项目、单环境部署

利用 Umi 的 `proxy` 配置，使用相对路径：

```typescript
// .umirc.ts
export default defineConfig({
  proxy: {
    '/api': {
      target: 'http://localhost:8000',
      changeOrigin: true,
    },
  },
});

// src/services/request.ts
const request = axios.create({
  baseURL: '/api',  // 只配置基础路径
  timeout: 30000,
});

// 使用时包含版本号
request.get('/v1/systems');
```

### 方案 4: 配置文件 + 运行时切换（⭐⭐⭐ 推荐）

**适用场景**: 需要运行时动态切换环境

```typescript
// src/config/environment.ts
export type Environment = 'development' | 'test' | 'production';

export const environmentConfig: Record<Environment, { apiBaseUrl: string }> = {
  development: {
    apiBaseUrl: '/api/v1',
  },
  test: {
    apiBaseUrl: 'http://test-api.example.com/v1',
  },
  production: {
    apiBaseUrl: 'https://api.example.com/v1',
  },
};

// 从 localStorage 或 URL 参数读取当前环境
export function getCurrentEnvironment(): Environment {
  const env = localStorage.getItem('APP_ENV');
  if (env && ['development', 'test', 'production'].includes(env)) {
    return env as Environment;
  }
  return 'development';
}

// src/services/request.ts
import { getCurrentEnvironment, environmentConfig } from '@/config/environment';

const env = getCurrentEnvironment();
const config = environmentConfig[env];

const request = axios.create({
  baseURL: config.apiBaseUrl,
  timeout: 30000,
});
```
