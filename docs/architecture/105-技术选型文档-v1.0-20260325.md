# 技术架构选型文档 – Smart Downloader 项目

---

## 1. 目标概述

- **核心功能**：高效、可靠地从任意 URL 下载文件，支持大文件、断点续传、并发下载、速率限制。
- **非功能需求**：
  - 高可用（单实例故障自动恢复）
  - 可观测（日志、监控、追踪）
  - 安全（凭证、API 密钥不泄露）
  - 可扩展（水平扩展、插件式存储后端）

## 4. 各组件职责

- **FastAPI Gateway**：
  - 接收前端请求（创建、查询、取消下载任务）
  - 参数校验（Pydantic 模型）
  - 将任务信息写入 PostgreSQL，并触发 Celery 任务

- **Celery Worker**：
  - 下载器核心实现（使用 `httpx` async streaming）
  - 支持分块、断点续传、速率限制（`aiohttp` + `asyncio.Semaphore`）
  - 将进度写入 Redis 缓存，实时推送至前端（WebSocket）

- **Celery Beat**：
  - 定时任务（如每日同步某批次文件）
  - 自动重试失败任务（指数回退）

- **PostgreSQL**：
  - `download_jobs` 表记录任务元信息（url、status、size、checksum）
  - `download_chunks` 表存储分块进度（offset、length、status）

- **MinIO / S3**：
  - 存放最终文件（分块合并后）
  - 通过预签名 URL 实现安全下载链接

- **Redis**：
  - 任务调度队列（Celery broker）
  - 进度缓存（如每 2s 更新一次）

- **Observability**：
  - **Prometheus** Exporter 暴露 `download_task_total`, `download_success_total`, `download_error_total`、`download_latency_seconds` 等指标
  - **Grafana** 提供实时仪表盘（任务数、并发、错误率）
  - **OpenTelemetry** 将每个下载请求的 span 发送至 Jaeger / Tempo，帮助定位慢节点

## 5. 部署方案

### 5.1 开发/本地环境（Docker‑Compose）
```yaml
version: "3.9"
services:
  api:
    build: ./frontend   # 若有前端 UI
    ports: ["8000:8000"]
    env_file: .env
    depends_on: [worker, redis, db]
  worker:
    build: ./smart_downloader
    command: celery -A downloader worker --loglevel=info
    env_file: .env
    depends_on: [redis, db]
  beat:
    build: ./smart_downloader
    command: celery -A downloader beat --loglevel=info
    env_file: .env
    depends_on: [redis, db]
  redis:
    image: redis:7-alpine
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: downloader
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: downloader
    volumes:
      - pgdata:/var/lib/postgresql/data
volumes:
  pgdata:
```
- 使用 `docker compose up -d` 即可启动完整本地环境。
- 前端 UI（若采用 React/Vite）可通过 `npm run dev` 单独运行。

### 5.2 生产环境（Kubernetes + Helm）
- 提供 `helm/smart-downloader` Chart，包含以下子 chart：
  - `api` Deployment/Service（FastAPI）
  - `worker` Deployment（Celery Worker）
  - `beat` Deployment（Celery Beat）
  - `redis` StatefulSet（持久化）
  - `postgres` StatefulSet（持久化）
  - `minio` Deployment（对象存储）
- Chart values 示例（`values.yaml`）：
```yaml
replicaCount: 3
image:
  repository: ghcr.io/your-org/smart-downloader
  tag: v1.0.0
redis:
  password: ${REDIS_PASSWORD}
postgres:
  username: downloader
  password: ${POSTGRES_PASSWORD}
minio:
  accessKey: ${MINIO_ACCESS_KEY}
  secretKey: ${MINIO_SECRET_KEY}
resources:
  limits:
    cpu: "500m"
    memory: "512Mi"
```
- 使用 GitHub Actions CI 自动构建 Docker 镜像并推送至 GitHub Packages，随后通过 Helm Upgrade 部署。

## 6. 可观测性与告警

| 指标 | 监控方式 | 阈值（示例） | 告警渠道 |
|------|----------|--------------|----------|
| `download_task_total` | Prometheus Counter | N/A | – |
| `download_success_total` | Prometheus Counter | N/A | – |
| `download_error_total` | Prometheus Counter | > 5/min | Slack / Email |
| `download_latency_seconds` (95th pct) | Prometheus Histogram | > 30s | PagerDuty |
| Worker Crash Rate | Prometheus `process_cpu_seconds_total` | 持续异常 | Slack |
| MinIO Storage Utilization | Prometheus `minio_bucket_usage_bytes` | > 80% | Email |

- 在 Grafana 中提供 **下载概览**、**错误率**、**吞吐量** 三大仪表盘。
- 使用 **OpenTelemetry Collector** 将 trace 数据发送至 **Jaeger**，便于定位慢速网络或存储瓶颈。

## 7. 安全与合规

1. **密钥管理**：所有 `OPENAI_API_KEY`、`NVIDIA_API_KEY`、`MINIO_SECRET_KEY`、`POSTGRES_PASSWORD`、`REDIS_PASSWORD` 均通过 **GitHub Secrets** 注入至 CI 或 **Vault** 动态注入至容器环境。
2. **最小权限原则**：
   - Redis 仅对 Celery 内部使用，无外部暴露。
   - MinIO Bucket 设置为私有，仅允许签名 URL 访问。
3. **审计日志**：`loguru` 输出结构化 JSON 日志至 `/var/log/downloader/*.log`，Logstash/FluentBit 收集后送至 ELK 或 Loki 进行归档。
4. **Compliance**：遵循 **PCI‑DSS**（如果涉及支付文件）及 **GDPR**（若下载个人数据），在文档 `compliance/README.md` 中列出对应控制措施。

## 8. 迁移 & 扩展路线图

| 里程碑 | 目标 | 关键实现 |
|--------|------|----------|
| **M0（当前）** | 基础功能（单节点） | FastAPI + Celery + Redis + PostgreSQL + MinIO（Docker‑Compose） |
| **M1** | 高可用 | K8s 部署，开启多副本；Redis Sentinel / PostgreSQL Patroni |
| **M2** | 多租户 / 配额 | 在 PostgreSQL 增加 `tenant_id`，在 API 层做配额校验 |
| **M3** | 云对象存储切换 | 抽象 `StorageBackend` 接口，支持 AWS S3、Azure Blob、GCS |
| **M4** | 业务插件化 | 通过事件总线（Kafka）支持业务方自定义下载后处理（如病毒扫描、转码） |
