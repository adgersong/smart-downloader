# 自动化防护方案（Opencode 常见问题）

本方案把 **9 大常见问题**（代码规范、硬编码、日志错误处理、依赖安全、测试覆盖、CI/CD、文档缺失、配置管理、运行时异常）全部转化为 **可配置、可复用、可审计** 的自动化防护手段。实现路径覆盖 **组织、流程、工具、代码层面**，并提供 **一键初始化脚本**，适用于所有新建或已有项目。

---

## 1️⃣ 代码规范（风格、Lint）
| 自动化方式 | 实现细节 | 触发点 | 产出 |
|---|---|---|---|
| **Pre‑Commit 配置文件** (`.pre-commit-config.yaml`) | - `ruff`（Python）<br>- `eslint` + `prettier`（TS/JS）<br>- `markdownlint`（MD）<br>- `stylelint`（CSS） | `git commit`（本地） | 代码在本地提交前必须通过 Lint，违规阻止 commit。 |
| **Opencode Skill**：`code‑style‑enforcer` | 自动生成 `.pre-commit-config.yaml`、`.editorconfig`、`pyproject.toml`、`tsconfig.json` 等。 | `opencode skill run` / `opencode init` | 统一团队风格，所有项目只需一次 Skill 安装。 |
| **CI 步骤** | 使用 `pre-commit/action@v3.0.0 --all-files`，确保即使本地 Hook 被跳过，CI 仍强制跑一次 Lint。 | Pull Request 检查 | PR 必须通过，避免不合规代码合并。 |

## 2️⃣ 硬编码（URL、密钥、魔法数字）
| 自动化方式 | 实现细节 | 触发点 | 产出 |
|---|---|---|---|
| **Secret‑Scan Hook** (`scripts/secret_scan.sh`) | 使用 `gitleaks`/`detect-secrets` 正则扫描提交文件，返回 findings 并阻止 commit。 | `git commit`、CI | 发现硬编码立即报错，提醒改为 env 或 Secrets Manager。 |
| **Opencode Skill – `hardcode‑cleaner`** | 自动生成 `gitleaks.toml`（自定义规则），并在 `pre-commit` 中注册 `gitleaks`。 | `opencode skill install hardcode‑cleaner` | 项目即拥有硬编码检测，无需手动配置。 |
| **配置化常量库** (`config/constants.py` / `constants.ts`) | Skill 自动生成 `constants` 模块并加入 `TODO` 注释提醒迁移。 | 编码时 | 开发者在 IDE 中看到 “常量未配置” 警告，强制迁移。 |
| **CI 检查** | 在 CI 中跑 `gitleaks detect --source=. --redact`，任何 findings `exit 1`。 | PR 检查 | 即使本地 Hook 被绕过，CI 仍能捕获硬编码。 |

## 3️⃣ 日志 & 错误处理（统一结构化日志、异常捕获）
| 自动化方式 | 实现细节 | 触发点 | 产出 |
|---|---|---|---|
| **统一 Logger Skill** (`logger‑factory`) | 自动生成 `logger.py`（Python）或 `logger.ts`（Node），封装 `loguru` 或 `pino`，提供 `log.info(msg, **ctx)`、`log.error(exc, **ctx)`。 | 项目初始化 | 所有业务代码只需 `from logger import log`，日志统一、JSON 输出、可索引。 |
| **异常基类 Skill** (`error‑handler‑base`) | 生成 `BaseError`（含 `code`、`msg`）及装饰器 `@handle_exceptions`，统一捕获并记录日志。 | 业务入口（API、任务） | 业务异常不再沉默，统一错误码便于监控。 |
| **CI 检查** | 在 `flake8`/`eslint` 中加入 `no-console`、`no-print` 规则，阻止 `print`/`console.log`。 | PR 检查 | 直接阻止残留 `print`/`console.log`。 |
| **日志审计工具** | Nightly CI 运行 `log-analyzer` 检查最近日志是否缺少 `error_code` 字段，生成报告。 | 每日 CI | 确保关键路径都有错误码。 |

## 4️⃣ 依赖安全（版本锁定、审计）
| 自动化方式 | 实现细节 | 触发点 | 产出 |
|---|---|---|---|
| **依赖锁定脚本** (`scripts/lock_deps.sh`) | 使用 `uv pip compile requirements.in -o requirements.txt`（Python）或 `npm ci`（Node）生成锁文件。 | `opencode skill run lock‑deps` 或 CI 前置 | 所有依赖均锁定，防止意外升级。 |
| **Security Scan Skill** (`dependency‑auditor‑skill`) | 自动在根目录生成 `auditor.yml`，在 CI 中执行 `dependency-auditor scan --config auditor.yml`，高危漏洞 `exit 1`。 | CI / PR | 自动化安全审计，发现即阻止合并。 |
| **Dependabot 配置** (`.github/dependabot.yml`) | 设置每日检查 `requirements.txt`、`package-lock.json`，自动提交安全升级 PR。 | 自动 | 持续获得安全补丁。 |
| **Git Hook** (`pre-push`) | 检查 `requirements.txt` 是否已提交，防止忘记推送锁文件。 | `git push` | 防止缺失锁文件导致不一致。 |

## 5️⃣ 测试覆盖（单元、集成、E2E）
| 自动化方式 | 实现细节 | 触发点 | 产出 |
|---|---|---|---|
| **Test Template Skill** (`test‑template‑generator`) | 自动生成 `tests/` 结构、`pytest`+`coverage` 配置、`jest`+`cobertura` 配置。 | `opencode skill run test‑template` | 新项目拥有完整测试框架，避免遗漏。 |
| **Coverage Gate** | CI 中加入 `coverage run -m pytest && coverage report -m --fail-under=80`（Python）或对应 `jest` 阈值。 | PR 检查 | 强制覆盖率 ≥ 80%。 |
| **E2E 自动生成** (`e2e‑scaffold`) | 自动生成 Playwright / Cypress 基础脚本，包含登录、公共函数。 | `opencode skill run e2e‑scaffold` | 防止缺失端到端测试。 |
| **测试报告上传** | CI 完成后 `actions/upload-artifact` 上传 `coverage.xml`、`jest-coverage.xml`，供 Dashboard 可视化。 | CI 完成 | 可追踪覆盖率趋势，及早发现下降。 |

## 6️⃣ CI/CD 配置（缓存、矩阵、快速回滚）
| 自动化方式 | 实现细节 | 触发点 | 产出 |
|---|---|---|---|
| **CI 模板 Skill** (`ci‑template‑builder`) | 自动生成 `.github/workflows/ci.yml`，包括：<br>1️⃣ `actions/cache` 对 `node_modules`/`~/.cache/pip`<br>2️⃣ 矩阵 (`python-version`, `node-version`)<br>3️⃣ `fail-fast: true`<br>4️⃣ `pre‑commit` 步骤<br>5️⃣ `deploy` 与 `test` 分阶段 | `opencode skill run ci‑template` | 新仓库即拥有最优 CI。 |
| **Rollback Script** (`rollback.sh`) | 部署失败返回非 0 时自动回滚到上一次成功的 Docker 镜像或 K8s 版本。 | `git push` → CI Deploy | 自动化回滚，降低故障恢复时间。 |
| **Pipeline Health Check** | 在 CI 中加入 `github-action-wait` 等待部署成功后再执行后续步骤，超时即标记失败。 | 部署阶段 | 防止半成品进入生产。 |

## 7️⃣ 文档缺失（MD、README、API 文档）
| 自动化方式 | 实现细节 | 触发点 | 产出 |
|---|---|---|---|
| **Doc‑Gen Skill** (`doc‑generator`) | 自动为每个模块运行 `pydocstyle` / `typedoc`，生成 HTML 或 Markdown 放入 `docs/api/`。 | CI（`on: push`） | API 文档始终同步，缺失时报错。 |
| **Doc‑Index Updater** (`doc‑index‑sync`) | 自动在 `000-文档索引.md` 中插入新文件名，使用 `scripts/sync_index.py`。 | `git commit` 或 CI | 文档索引保持最新。 |
| **Markdown Lint Hook** (`pre‑commit` `markdownlint`) | 检查标题层级、链接有效性、拼写错误。 | 本地提交/CI | 防止低质量文档进入仓库。 |
| **README‑Sync Skill** | 检测 `README.md` 中的概览是否与 `pyproject.toml`/`package.json` 中的 `description` 保持一致，不一致时报错。 | CI | 项目元信息统一。 |

## 8️⃣ 配置管理（环境、Secret、动态加载）
| 自动化方式 | 实现细节 | 触发点 | 产出 |
|---|---|---|---|
| **Env‑Config Skill** (`env‑config‑builder`) | 自动生成 `.env.example`、`config.yaml`、`config/schema.py`（pydantic）以及 `scripts/validate_env.sh`。 | `opencode skill run env‑config‑builder` | 把所有硬编码迁移到统一配置，启动时自动校验。 |
| **Secret‑Sync CI** | 在 GitHub Actions 中使用 `secrets-context` 注入 `AWS_SECRET_*`、`AZURE_KEYVAULT_*`，缺失直接 `exit 1`。 | CI Deploy | 防止缺失密钥导致部署失败。 |
| **Config‑Validator Hook** | `pre‑push` 运行 `python -c "import config; config.validate()"`，异常阻止 push。 | `git push` | 确保配置信息合法后才能发布。 |
| **Dynamic Config Loader** | `config_loader.py` 自动读取 `ENV`、`.env`、`config.yaml`（优先级：Env > .env > yaml），并在 `settings` 中提供 `as_dict()` 给日志输出。 | 程序启动 | 统一入口，避免散落硬编码。 |

## 9️⃣ 运行时异常（资源泄漏）
| 自动化方式 | 实现细节 | 触发点 | 产出 |
|---|---|---|---|
| **Resource‑Watcher Skill** (`resource‑watcher`) | CI 中跑 `python -X dev -m tracemalloc run_tests.py`，将 `tracemalloc` 生成的快照与阈值比较，超过 10% 报错。 | CI 测试阶段 | 捕获潜在内存泄漏。 |
| **上下文管理模板** | 自动生成 `utils/context.py`，提供 `resource_manager` 装饰器，用 `with` 包装文件、网络、DB 连接。 | 代码生成 | 开发者只需 `@resource_manager`，避免忘记关闭。 |
| **CI 警报** | 使用 `pytest --durations=10` 记录最长函数，若出现未关闭资源在日志中标记 `RESOURCE_LEAK`，CI 发送 Slack 警报。 | CI 完成 | 及时发现泄漏热点。 |
| **统一关闭 Hook** | FastAPI/Flask 中加入 `@app.on_event("shutdown")` 统一关闭 DB、Redis、文件句柄。 | 程序退出 | 确保全局资源一次性回收。 |

## 📦 完整的一键部署脚本（示例）
```bash
#!/usr/bin/env bash
# init_opencode_project.sh
set -e

# 1️⃣ 安装所有官方 Skill
opencode skill install code-style-enforcer
opencode skill install hardcode-cleaner
opencode skill install logger-factory
opencode skill install dependency-auditor-skill
opencode skill install ci-template-builder
opencode skill install doc-generator
opencode skill install env-config-builder
opencode skill install test-template-generator
opencode skill install resource-watcher

# 2️⃣ 生成项目根目录关键文件（会被 Skill 覆盖）
git add .
git commit -m "chore: init opencode quality & CI stack"

# 3️⃣ 推送到远端触发 CI
git push origin main

echo "✅ 项目已完成自动化初始化。后续仅在 PR 中编写业务代码即可。"
```

> 只需在 **每个新仓库** 运行一次 `init_opencode_project.sh`，即可获得完整防护体系。
